### 统计算法

本报告所有 `*_median`、`*_p95` 字段均使用 **nearest-rank percentile（C=1）算法**，由 `stage7_deployment/multivalidator/tools/summarize_runs.py:_nearest_rank` 实现：取 `rank = ⌈p × n⌉`，返回排序后第 `rank` 位（1-indexed）。对偶数 `n`（本报告 n=10），中位数返回 `sorted[4]`（即"低位中位数"，lower median），不取 `(sorted[4]+sorted[5])/2` 平均值。同一数据集若改用 R 的 `median()`（取均值）或 NumPy 默认线性插值法重算，对偶数 n 会与本报告差一位。复核脚本 `tools/audit_formal_60.ps1` 与已发布 summary 的中位数差异即源于此口径分歧（参见 `reports/audit_recheck_*.md`）。

## 解释边界

`recovery_time_ms` 只对 `pause_container` 故障有定义。因此，baseline、delay、loss、pressure 场景中该字段为空是预期行为，不应视为证据缺失。

本结果仍是单机 Docker Desktop 实验，应在论文中明确其边界：同一宿主机 CPU、内存、磁盘和 Docker bridge 网络会共享资源；结论应表述为“本机 N=7/f=2 Docker 多验证者部署下的实测行为”，不应外推为跨物理节点生产网络性能。
