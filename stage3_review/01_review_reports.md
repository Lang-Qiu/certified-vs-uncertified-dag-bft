# 评审报告 1 — EIC 主编(期刊契合度 / 原创性 / 显著性)

## 总体评价
本文选题切中 DAG-BFT 共识当前最活跃的争论之一,并采取了一个不常见而有价值的姿态:不提出新协议,而是质疑一个被领域默认接受的判断("去认证免费降延迟")。这种批判—重构型论文若做得好,其学术价值高于又一个增量协议。本文整体达到了顶级会议 critique 论文的写作水准。但作为主编,我对其"显著性"——即这一 reframing 是否真正改变了读者此后的思考与行动——持保留意见。

## 优点
1. **姿态稀缺**:在一个以"提出协议+报告 benchmark"为主流范式的方向里,本文选择做坐标系批判,填补了 SoK 类工作未触及的空白(§2.7)。
2. **方法论自觉突出**:SubRQ0(§1.2、§3.1)把"混淆变量"这一内部效度问题前置为全文起点,这是成熟的研究品味。
3. **诚实声明到位**:§1.4 主动声明条件化结论的误用风险,§9 系统列出局限,这种自我约束在批判性论文中尤为可贵。

## 主要关切
- **[E1 — MAJOR] 贡献 C 的显著性是"解释性"而非"生成性"。** 深层轴(§8)能够重新归类现有协议、并安放 Adelie/DispersedLedger 这类二分法尴尬的中间设计(§8.4),这是真实的解释力。但一个坐标系的最高价值在于**预测一个尚未被占据的设计点**。本文的深层轴没有指出任何"二维平面上空着、值得去做"的区域。建议:在 §8 增加一小节,用深层轴推演一个现有协议谱系中不存在的设计点(例如"提交后 enforcement + 批量 reconciliation + 纠删码承诺"的组合),哪怕只作为 conjecture——这会把贡献 C 从"换坐标"提升为"用新坐标看见新东西"。
- **[E2 — MAJOR] 全文无任何经验锚点,使中心主张目前不可检验。** 论文的核心结论是"延迟优势会反转",但 ρ、Δ_save、Δ_recover 三个决定性参数从未被任何真实测量约束。读者无法判断 ρ>ρ* 在真实部署中是常态还是罕见边角。这不必是完整实证,但至少需要从已发表测量(如 Shoal++ [38]、Autobahn [49] 的故障实验)中提取数量级锚点。
- **[E3 — MINOR] 行文存在过度签注与论点复述。** 中心主张在摘要(中英各一)、§1.1–1.3、§5 开篇、§8.1、§10 反复出现近 7 次;"本章是全文核心"一类元叙述偏多。建议精简,信任读者。

## 编辑视角结论
本文是一篇有想法、写作成熟的批判性论文,但其贡献当前停在"重新描述"层面,距离"重新定义"尚有一步。属 **Major Revision** 量级:E1、E2 不解决,论文会被读成"一个聪明的观察",而非"一个该被记住的判断"。

# 评审报告 2 — Reviewer 1:方法论(研究设计 / 形式化严格性 / 可复现性)

## 总体评价
本文的方法论框架(不变量分解 + 受控 minimal-pair + C1-B/C1-C 判据)设计得相当用心,体现了对"如何避免归因错误"的清醒认识。但框架的**严格性兑现**与其雄心不完全匹配:命题 1 的证明有一处实质性缺口,核心定量产物 ρ* 依赖一个被论文自己否认的假设,而 minimal-pair 框架在 §3.5 后实际未被执行。这些不是致命伤,但必须在修订中正面处理。

## 优点
1. C1-B 三分法 + C1-C 双判据(§3.4)是一个真正可证伪化的努力:作者明确意识到"重新分配"若无判据会沦为同义反复,并用"成本台账可见 + 证明步骤依赖"双条件去钉死它。这是方法论上的亮点。
2. §3.5 把"minimal pair 不可构造"转化为实质发现,逻辑上自洽且有勇气。
3. 仿真代码随论文提供、可复现,§9 与 README 对模型局限有诚实标注。

## 主要关切
- **[M1 — MAJOR] 命题 1 的敌手构造有严格性缺口。** §6.2 的证明写道"将正确验证者划分为两组 P₁、P₂,每组规模足以使提交推进……X 与 X′ 各自都能在其所在分组中聚集到提交所需的引用支持"。但在 n≥3f+1、f 拜占庭的标准模型下,正确节点仅 2f+1 个;DAG-BFT 的提交通常需要 2f+1 的 quorum 支持。两个不相交、各自能独立推进提交的正确节点组,需要 ≥2(2f+1)=4f+2 个节点,超过 n=3f+1(f≥1 时)。**即使让 f 个拜占庭节点同时参与两组,仍需 ≥2f+2 个正确节点,与 2f+1 矛盾。** 因此"划分为两个各自能提交的组"这一构造按字面无法在 f<n/3 下成立。命题 1 的结论(非等价性必须被 enforce)我相信是**对的**,但其正确证明应走 **quorum 交集**路径:等价区块使同一 (author, round) 槽位在两个相交 quorum 中分别以 X、X′ 被计入,而两个 2f+1 的 quorum 必交于 ≥f+1 个节点(含 ≥1 个正确节点)——是等价破坏了交集论证所依赖的一致性。请重写 §6.2,明确 commit 的 quorum 定义并以交集论证替代"分组"叙述。
- **[M2 — MAJOR] ρ* 作为精确临界点,依赖一个论文自己否认的独立性假设。** §7.2 由 净优势=Δ_save−ρ·Δ_recover 解出 ρ*=Δ_save/Δ_recover,把 ρ 与 Δ_recover 当作独立变量。但 §7.4 与 §9 明确承认二者在拥塞反馈下相互耦合。若二者耦合,ρ* 就不是一个良定义的标量阈值。建议:要么在 §7.2 把"ρ 与 Δ_recover 独立"作为显式建模假设写明并把 ρ* 的有效性限定在该假设内,要么放弃 ρ* 作为精确阈值、仅保留"存在一个翻转区"的定性陈述。
- **[M3 — MAJOR] Monte Carlo 仿真"验证"的对象被表述过宽。** §7.2 称仿真"验证了该解析模型的自洽性"。实际上,仿真的逐轮随机过程其均值收敛到闭式期望,这是**期望的线性性**的体现——它验证的是"公式被正确实现",而非"模型贴合现实"。建议把 §7.2 措辞改为"实现层面的交叉核对(implementation cross-check)",并明确指出仿真唯一真正新增的信息是净优势的**方差**。当前措辞有把算术自洽包装成模型验证之嫌(虽然 §9/README 已诚实标注,正文用词仍需收紧)。
- **[M4 — MINOR] C1-C 判据(b)的应用只被断言、未被展示。** §5.2 称"协议的安全性证明确实在某一步依赖'等价区块不会被提交'",但未给出该证明步骤的具体引理。判据原则上可操作,应至少对一个协议(如 Mysticeti)给出一处真实的证明步骤引用作为 worked example。
- **[M5 — MINOR] §3 的 minimal-pair 框架在 §3.5 后实际未被执行。** 第 4–7 章并非一项受控 minimal-pair 研究,而是一次跨异质协议的结构化不变量追踪。建议在 §3.5 末或 §5.1 明确这一点,以免 §3 的框架"超售"了实际交付的严格性。

## 方法论视角结论
**Major Revision**。M1 是必须修复的严格性缺口;M2、M3 是表述与范围问题,改对措辞即可,不需推翻结论。

## 量规维度评分
- **规范性(主责)= 76/100**:IEEE 格式、声明、图表规范到位;主要扣分在命题 1 证明缺口(M1)、ρ* 的范围未声明(M2)、仿真用词过宽(M3)。
- **完整性(副责)= 81/100**:论证链闭环,但 M4 的 worked example 缺失使判据应用链有一处未坐实。

# 评审报告 5 — Devil's Advocate(核心论点挑战)

## 最强反论(Strongest Counter-Argument)

本文中心主张——"去认证是结构性替换,而非可分离的优化"——存在**因构造而近乎不可证伪**的风险。三分判据把任一不变量的命运钉为 ①(平移)或 ②(削弱+补偿),而 ③(消除)被定义为"保证被真正放弃且无补偿"。问题是:任何已发表、能正常工作的协议都是安全的;一个安全的协议,按定义其安全性不变量必被某种机制维持。于是"去认证从不产生 ③"几乎是**"工作协议"定义的同义反复**,而非经验发现。论文 §5.7 自己也承认:③ 只能在语料库 C 内被排除,且需靠构造一个"删认证且不加补偿"的稻草人协议来反衬。把判据机器拆掉,真正非平凡的内容其实很窄:**可用性补偿的成本是一笔或有负债(contingent liability),而非零**。这是一个真实且有价值的观察——但它是**一个观察**,不是一座三层理论。本文的风险在于:用 ①②③、C1-B、C1-C、命题 1、深层轴这一整套脚手架,包装了一个本可以两段话讲清的洞见,而脚手架的体量让读者(和作者自己)误以为交付了比实际更多的东西。一个尖锐的读者会问:剥掉形式化外衣,本文比"安全协议必然 enforce 其安全不变量,而可用性是物理的、要花钱"多说了什么?

## 问题清单(Issue List)

| 编号 | 严重度 | 维度 | 位置 | 问题 |

## 被忽略的替代解释 / 路径
- 论文隐含地把 certified 协议的最坏情况当作固定基线,只让 uncertified 的最坏情况随故障膨胀。一个公平的成本台账必须**让双方都退化**:certified DAG 在故障下也有 RBC 重传风暴、view-change 开销。"延迟优势会反转"的结论,部分可能来自这种不对称记账,而非去认证本身。
